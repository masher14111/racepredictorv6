# `data/` — Artifact Inventory & Rebuild Guide

Every file under `data/` is one of three kinds:

- **source-of-truth** — captured from the network or hand-authored; losing it means re-scraping (slow) or losing user state. Never delete casually.
- **regenerable** — a deterministic output of a pipeline step; safe to delete and rebuild with the listed command.
- **stale/scratch** — leftover from a one-off or an abandoned code path; safe to delete, nothing rebuilds it.

The pipeline flow is: `scraper/ → data/historical/*.parquet (+ raw/) → utils.normalizer → data/unified_races.parquet → features.builder → data/features/training.parquet (+ data/features.parquet) → models.train → models/`, then `models.predictor → data/predictions.json`.

Run the whole chain with `python pipeline.py` (add `--skip-scrape` to reuse existing historical parquets).

## Git tracking

`.gitignore` excludes all of `data/*.parquet`, `data/**/*.parquet`, `data/races.db*`, `data/cache/`, and `data/_*`. The `historical/raw/` HTML/`.gz` files are **not** git-ignored but are untracked — do not commit them (2 GB).

## Notes

- `historical/raw/sporting_life/` is the single largest artifact (~2.0 GB, ~90 % of `data/`). It is an insurance archive for re-extraction; the structured data already lives in `historical/betsp.parquet`. Deleting it loses only the ability to re-parse raw HTML without re-scraping.
- `races.db` is the only artifact holding **non-regenerable user state** (bets, bankroll). Back it up before any cleanup.
