## The data question, answered empirically first

STATE said `horse_speed` is a finishing-percentile proxy — still true, and left
byte-identical. The stage hinges on whether real timing exists. It does, in a
source already on disk and already trusted for settlement: the 33,927-document
raw Sporting Life archive (`execution/race_facts.py` mines it for Rule 4 /
dead-heats). Probed before designing anything
(`reports/improvement/11/00_probe_archive.txt`, 40-day sample):

- `race_summary.winning_time` (`"5m 14.84s"`) on **98.50%** of race documents
- `race_summary.distance` (`"2m 4f 56y"`) on **100%**
- per-ride `finish_distance` margins, vocabulary numeric + `¼½¾` + `nse/sh/hd/nk/dh`
- **no sectional field of any kind** — a recursive key scan for
  `sectional|split_time|furlong_time|pace_figure` returned nothing.

Margins are **INCREMENTAL** (gap to the horse in front), established by
measurement not assumption: 373 sampled races contain a decrease somewhere down
the finishing order, impossible under a cumulative reading, vs 34 merely
cumulative-compatible. So beaten-lengths-behind-winner is a running sum.

## Contract (features/measured_timing.py, 50 tests)

Units yards / seconds / lengths / yards-per-second, each in its column name.
**Non-runners excluded** (no performance); a runner that did not complete gets
`finished=False` and a **null** time — never imputed, never a slow finisher.
A race with no parseable time/distance emits no rows. `available_from` = the
race's own local off time, mirroring `race_facts._off_datetime`'s UTC→local
conversion so the join key is byte-identical to the settlement archive's
(asserted in test). **Only the winner's time is published**: a beaten runner's
time is `winning_time + cumulative_lengths / lengths_per_second`, where
`lengths_per_second` is a *declared parameter*, not a measurement — every column
through it is named `est_*` so it cannot be mistaken for a published figure.
`beaten_lengths` and `winner_speed_yps` are exact arithmetic on published data.

## Normalized performance (features/measured_speed.py, 13 tests)

Par = strictly-prior mean/std of `log(winner speed)` per key, hierarchical
backoff over 8 levels (course×surface×race-type×exact-distance×going → …→
global), most specific with ≥15 prior races wins; `par_level` records which, so
a thin cell is always identifiable. Fitted by accumulating whole same-instant
blocks and taking the cumulative total *before* each block — which is what
delivers both invariances. Figures: `measured_speed_pct` (100× log-ratio to par)
and `measured_speed_z` (÷ prior par spread). Pre-race family = **strictly prior**
horse aggregates through `features/_trailing_fast.py`, so it inherits D26's
market-duplicate collapse and D39's real off-time ordering: `msf_last`,
`msf_mean3`, `msf_mean6`, `msf_trend`, `msf_distance`, `msf_going`, `msf_rank`.
Registered as `models.features.MEASURED_SPEED_FEATURE_COLS` and appended to
`CANDIDATE_INDEPENDENT_FEATURE_COLS` — the established D27/D33 experimental
switch: additive, absent from `FEATURE_COLS`, so **no trained bundle changes**.
`horse_speed` is untouched.

5,561-row dev-OOS panel**; each pair differs only by the added family. The

**Whole-race uncertainty** (2,000-resample bootstrap over whole races, paired):
- condlogit indep: delta **+0.01054**, CI95 **[+0.00250, +0.01866]**,

  The market already prices this information.
- lgbm indep: delta +0.01055, CI95 [-0.03171, +0.05185] — **not significant**,

**Sensitivity to the one declared constant** (`lps_sensitivity.json`): rebuilt at

**Verdict — retain, as a candidate only.** Documented evidence: a genuine,

~0.010 of the ~0.217 price-free gap to the market. No arm beats the market, so
nothing is promoted and NO-GO stands.
