## Defects repaired in this stage

- **F1 (HIGH, owner step 04)** — `_trailing_fast._bounds` (`strict=False`) and
  `_windowed_win_rate_days_core` cut priors POSITIONALLY inside a date-only
  `race_date`. Before: `trainer_win_rate` counted 126,408 same-day priors that
  ran LATER (46.48%), 25.36% of runner-events; `jockey_win_rate` 132,594
  (49.95%), 29.98%. Repaired by cutting on the real off-time recovered from
  `race_uid` (`_order_instants`), with a content-derived tiebreak
  (`_chrono_rank`) so the `lookback_runs` tail cap is row-order invariant, plus
  `build_inference_matrix` now admitting today's already-run races so serving
  sees the same history as training. After: **0** later-running priors, **0**
  rows moving under a row shuffle on all 10 window paths. Feature impact for
  step 10: `trainer_win_rate` moved on 20.59% of rows, `jockey_win_rate` 20.91%,
  `historical_win_rate` 0.00%. See D39.
- **F7 (HIGH, found here)** — the trainer/jockey day windows compared a
  hard-coded ns-per-day constant against a microsecond-resolution
  `race_date.asi8`, so `window_days=14` meant 14,000 days. The "hot" 14-day rate
  equalled its own 90-day baseline on 100.00% of comparable rows, making
  `{trainer,jockey}_form_zscore` structurally ~0 — four `FEATURE_COLS` members
  carried no signal. Repaired via `_ticks_per_day`. After: 14d mean n=18.11 vs
  90d 79.80; `trainer_form_zscore` non-null 70.58%, std 0.91. See D41.
- **F3 (MEDIUM, owner step 10)** — `race_complexity` is market-reactive
  (perturbing prices moves it on 100% of probe rows) yet sat in
  `PRICE_FREE_FEATURE_COLS`. Repaired at source via
  `models/features.MARKET_DERIVED_FEATURE_COLS`; it stays in `FEATURE_COLS` and
  no trained bundle changes (each carries its own `meta["feature_cols"]`).
  `audit/leakage.py::check_provenance` now enforces the strip. See D40.
- **F5 (LOW)** — `runner_status` had no consumer; `_is_non_runner` now ORs the
  declared racecard status with the odds-feed jockey marker.
- **F6 (LOW)** — `_canonical_id("nan")` minted a real entity id, pooling 501
  horses into one fake jockey/trainer (1,002 labelled rows, 0.18%). A narrow
  rendered-null token set now returns `None` at the normalizer boundary.
- **F2 (HIGH, attempt 1, D38)** — the market-duplicate collapse also deleted a
  yard's other runners (6.50% of trainer runner-events). Re-verified this
  attempt: runner-events lost **0**, recomputed `trainer_win_rate` differs on
  **0** rows.
