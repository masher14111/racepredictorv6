  already satisfies scope item 3/4's reference-vs-executable separation for
  the execution layer.

## Defects found and fixed (live ticket-issuance path)

Both live only in `scripts/daily_paper_loop.py::_today_tickets` / `run()` —
the snapshot store itself was already correct.

1. **False "timestamp in the future" on every live candidate.**
   `_today_tickets` was called with `now=day_start` (midnight UTC, needed so
   `build_ticket`'s idempotent `issued_at`-hashed ticket_id is stable across
   same-day re-runs — `_day_start`'s own docstring). That same day-truncated
   value was ALSO passed to `evaluate_race`/`evaluate_candidate` as the gate's
   decision instant, so `age_seconds = ts - fetched_at` went negative for any
   runner whose own cached price (the pre-existing "runner" fallback path in
   `execution/gates.py::_quote_view`) was fetched intraday — which is every
   real case. Negative age trips `executable_price:timestamp_in_future`
   (`execution/gates.py:730`), a fail-closed "no bet" for a completely bogus
   reason, on every runner, every day. Reproduced directly:
   `evaluate_candidate(..., now=day_start)` -> `quote_age_seconds=-32370.0` and
   `timestamp_in_future` in `pass_reasons`; `now=<real decision instant>` ->
   `quote_age_seconds=30.0`, reason gone. Currently silent in production only
   because the model verdict is NO-GO (every candidate is forced PASS
   regardless), so nobody had observed a live CANDIDATE actually blocked by
   it — but the moment the model reaches GO this would silently veto every
   live bet.
   Fix: `_today_tickets` now takes `now` (ticket-id issuance instant, stays
   day-truncated) and a separate `evaluated_at` (the real wall-clock instant,
   used for `evaluate_race`'s gate/freshness arithmetic). `run()` passes
   `evaluated_at=stamp`.

2. **Live pricing never read through the snapshot store.**
   `_today_tickets` never passed `quotes=` into `evaluate_race`, so every live
   decision used the "runner" fallback (whatever price happens to be cached
   in `predictions.json`) even though `daily_paper_loop.run()` already
   constructs a `SnapshotStore` (used only for settlement's `closing_quote`).
   `execution/gates.py::_quote_view`'s own docstring says the runner fallback
   is "only for surfaces that have no snapshot store wired in" — this surface
   does have one. Fix: `_today_tickets` gained an optional `snap_store`
   param; when supplied, each runner gets a `latest_quote(race_uid, horse_key,
   evaluated_at, market_type="WIN")` lookup threaded into `evaluate_race`, so
   the ticket is priced from the tested, staleness-checked, append-only store
   rather than an untracked cache. `run()` passes the loop's own `snap_store`.

Both fixes are additive/keyword-only; the one production call site
(`run()`) and both changes were exercised end-to-end.

## Documentation correction (scope item 4)

`backtest/holdout.py` and `backtest/data.py` (the CatBoost/LightGBM GO/NO-GO
harness that feeds `execution/model_gate.py`) previously asserted `ppwap`
(Betfair pre-play weighted-average) was "a real pre-off price you could have
matched" / "we never claim a price we could not have matched". `ppwap` is a
volume-weighted AVERAGE over the whole pre-off period, not a single quote
proven fillable at one instant — exactly the overclaim step 07 scope item 4
warns against. Corrected both docstrings to describe it as a
chronologically-safe reconstruction / diagnostic proxy, pointing to
`execution.snapshots.SnapshotStore` as the genuine captured-executable-price
evidence. Docstring-only; no computation, threshold or model verdict changed
(`tests/backtest` 115 passed unchanged). Other files using the same language
(`models/train_lgbm.py`, `audit/report.py`, `scripts/calibration_audit.py`,
etc.) were not rewritten this session — same overclaim risk, deferred (see
next action).

## Unresolved limits (named, not fabricated)

- Live odds scrapers (`livescorebet`/`boylesports`/`paddy_power`/`betsp`)
  capture WIN market only — no live PLACE executable-price capture exists.
  Consistent with D24 (live inference serves WIN rows only); not a defect,
  but PLACE backtesting/replay has no live-captured executable price to use.
- No explicit non-runner/withdrawal column in `odds_snapshots`; a withdrawal
  is only inferable as "stopped being re-captured, ages into stale" (now
  tested). A bookmaker that leaves a withdrawn runner's stale price on the
  board without dropping it would not be caught until staleness passes
  `max_age_seconds`.
- The live ticket-issuance path (`execution/gates.py` via
  `daily_paper_loop.py`) has no "minutes before off"/race-started safeguard —
  `execution/safeguards.Safeguards` (which does have
  `started_race_buffer_seconds`) is wired into `execution/simulator.py`
  (backtest) but never called from `daily_paper_loop.py`. Consistent with
  step01's own finding (CONTRACTS.md: the 10-minute cutoff is a "provisional
  research assumption... does not change any live/service behavior"), so not
  a regression from this step, but worth a named follow-up — out of this
  step's scope (odds capture/replay, not staking safeguards).
- ppwap/morningwap fillability overclaim was corrected only in the two files
  directly in this step's "pricing consumers" remit
  (`backtest/holdout.py`/`data.py`); the same phrasing pattern exists
  elsewhere (`models/train_lgbm.py`, `audit/report.py`,
  `scripts/calibration_audit.py`) and was not touched this session.
