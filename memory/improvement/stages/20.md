## Root-cause fixes (additive; frozen training contract untouched)

1. **B5 identity** — new `execution.snapshots.race_key(venue, race_time)`: ALWAYS venue-qualified,
   minute-precision (`norm_venue|YYYY-MM-DDTHH:MM`, matching `race_facts_key`'s scheme), additive
   alongside the unchanged `race_uid` (which stays exactly as documented — a bare off-time, no
   venue, second precision — for full backward audit-trail compatibility). Threaded through
   `execution.gates.race_key(race)`, `execution.tickets.Ticket.race_key`, and
   `SnapshotStore.quotes_as_of/latest_quote/best_quote`'s new optional `race_key=` filter (narrows,
   never widens — omitting it preserves every existing caller's behaviour exactly).
   `scripts.daily_paper_loop._today_tickets` now passes both `race_uid` and `race_key` into the
   snapshot lookup, so two venues sharing an off-time can never satisfy the same quote lookup.
2. **B5 off-time disagreement (GAP-C)** — new `features/_race_reconcile.py::reconcile_live_race_times`:
   clusters near-off-times (<=180s, well under the measured 600s real floor) at ONE venue, requiring
   genuine runner-name overlap between adjacent slots (preferring the highest-priority source's time,
   D23's `_SOURCE_PRIORITY`) before merging; a close pair with NO confirmed shared runner is
   QUARANTINED (excluded, reason recorded to `data/execution/identity_quarantine.json`), never
   guessed either way. Wired ONLY into `features.builder.build_inference_matrix` (today's live rows)
   — `build_training_matrix` and every frozen dev/final-holdout matrix (D42) are untouched; this
   cannot retroactively change any evaluated window's race membership. Also (bonus, unrequested):
   because reconciliation runs before `fuse_sources`, a runner's WIN and PLACE rows disagreeing by a
   minute across sources now correctly land in ONE race instead of being split into two.
3. **B6 operating cutoff** — new `operating_cutoff` gate condition in `execution.gates.evaluate_candidate`
   (12th condition; wired to the existing, previously-uncalled `cfg.safeguards.block_started_races`/
   `started_race_buffer_seconds`), evaluated against the real `evaluated_at` wall-clock instant, never
   a day-truncated stand-in. An already-off or inside-buffer race now PASSes with an explicit
   `operating_cutoff:*` reason (full disclosure kept, per the ticket module's own philosophy), rather
   than being silently ticketed (GAP-A). New `scripts.daily_paper_loop._predictions_freshness_reason`
   rejects the WHOLE predictions.json (issues nothing that cycle) when `generated_at` is unreadable,
   future-dated beyond 120s clock-skew tolerance, older than 20h, or on a different Dublin calendar
   day than `evaluated_at` (via `utils.timezone.to_local`, DST-safe) — fixes GAP-B (a stale card no
   longer gets re-ticketed under today's stamp).
4. **Issuance vs. dedupe separation** — `build_ticket`/`make_ticket_id` gained a `dedupe_key` param,
   separate from `now`: `Ticket.issued_at` is now the REAL `evaluated_at` instant; the stable per-day
   `dedupe_key` (unchanged value, just no longer forced onto `issued_at`) still makes a same-day
   re-run mint identical `ticket_id`s. Previously every ticket's disclosed issue time was always a
   fake midnight — a genuine, if invisible, provenance defect, independent of B6/B7.
5. **B7 provenance** — `models.predictor.Predictor._model_manifest()` sha256-hashes every artifact
   file it actually loaded (meta.json, each target's `.bin`/`_calib.pkl`, value/FL calibrators when
   enabled) into one `model_content_hash`, plus a `feature_schema_version` hash of the trained-on
   column list; written to the SAVED manifest `data/execution/served_model_manifest.json` (overwritten
   every cycle) and into `predictions.json["provenance"]` alongside a `prediction_cycle_id` and
   `decision_time`. New `execution.config.config_fingerprint(cfg)` hashes the loaded `ExecutionConfig`.
   `daily_paper_loop` merges both into each ticket via `build_ticket(provenance=...)`; migration 8
   adds `race_key`/`model_content_hash`/`feature_schema_version`/`config_hash`/`prediction_cycle_id`/
   `provenance_complete` to `paper_tickets`. `_forward_ledger`'s `qualified` mask now requires
   `provenance_complete` in addition to settled — an unprovenanced or partially-provenanced CANDIDATE
   can never count toward the forward gate, satisfying "missing/inconsistent provenance excludes
   formal eligibility" structurally, in the one place `forward_gate._qualified` already reads.

## A real migration defect found and fixed while applying it to the live store

First version of migration 8 tried to `UPDATE odds_snapshots SET race_key=...` for the backfill —
`odds_snapshots` carries migration 4's `RAISE(ABORT)` append-only triggers, so this raised
`IntegrityError` **on the real store** (4,806 rows; a fresh empty test db never exercised it, which
is why offline unit tests alone missed it) and left the db mid-migration (columns added,
`user_version` still 7). Restored from the pre-migration backup, fixed the migration to never touch
`odds_snapshots` via UPDATE (its `race_key` is intentionally NULL on every pre-existing row — a
one-time, bounded gap; new snapshot writes populate it at write time regardless) and to guard every
`ALTER TABLE ADD COLUMN` with a `PRAGMA table_info` existence check so a second attempt after any
partial failure resumes instead of raising "duplicate column". Two regression tests reproduce the
exact crash and the exact resume-after-crash shape before asserting the fix. Detail, backup path and
rollback: `reports/improvement/20/MIGRATION.md`.
