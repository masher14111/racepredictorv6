## Acceptance

- Market-only / independent-only / combined on identical eligible races, with
  log loss, Brier, ECE and calibration by odds band, field size, racing regime
  (surface × distance), region and selected-bet subset, with sample counts.
  **Met** — `scorecard_12.json`, `breakdowns/calibration_by_stratum.csv` (156
  rows). Caveat recorded in the scorecard: A/E is ≈1.000 by construction for any
  *race-complete* stratum (within-race normalisation), so field-size / regime /
  region rows must be read on `race_log_loss` and `brier`; odds-band and
  selected-bet rows cut across a race and are the informative A/E slices.
- Changing only an executable quote cannot change ability or the reference
  probability. **Met on real data** (710 raw races rebuilt twice through
  `features.builder._derive_all`): perturbing only `odds_decimal`/`sp` (both
  100% null historically → filled with a realistic best-of-N overlay, then moved
  1.5-4×) leaves the price-free probability, the reference probability and the
  blend **bit-identical** (max|delta| = 0). Control: perturbing the reference
  price moves the reference line (0.572) while the price-free probability stays
  bit-identical, so the probe is not vacuous. 13 market-assisted features do
  react (`implied_prob`, `market_rank`, `race_complexity`, `price_steam_pct`, …)
  — by design, and precisely why `combined_market` is not an ability estimate.
- Missing/incomplete reference books and non-runners tested explicitly.
  **Met** — one unpriced runner NaNs that race's reference probability AND its
  blend (556/556 rows), leaves other races bit-identical, and leaves the
  independent estimate defined; a withdrawal renormalises survivors to 1.0
  (max|sum-1| 2.2e-16 over 200 real races) with zero reordering and no imputed
  probability for the withdrawn horse. Also unit-pinned in `test_blend.py`.
- Candidate coefficients, calibration artifacts, input hashes and cutoff rules
  in a separate experiment directory; promoted artifacts untouched. **Met** —
  `git status` shows no modification to `models/*.bin`, `models/*_calib.pkl`,
  `models/lgbm_won_v3.txt`, `models/lgbm_v3_meta.json`; the only new file under
  `models/` is `blend.py`.
- A disappointing candidate reported as such, methods not re-altered after the
  panel was inspected. **Met.**

## Audited finding — SHIPPED price adjustment (measured, NOT fixed here)

`models.predictor._score_value` feeds `_apply_fl_recalibration` the
**executable** best-of-N board price (`_effective_decimal`), while
`models/fl_oddsband_v3nf_calib.pkl` was fitted on the pre-off **reference**
price (`docs/calibration/fit_fl_recalibrator.py`, `bet_price` = ppwap). Measured
on the 308 real live runners in `data/predictions.json` carrying both prices
(mean executable/reference ratio 1.0143): the served `value_win_prob` differs
from its reference-price value by mean 0.00092 / max 0.05275, and a **+10% move
in the executable quote alone** shifts it by mean 0.00793 / max 0.04319 — on a
0.11 base rate, a ~7% relative swing in a served probability caused purely by a
bookmaker moving a quote. `value_win_prob_independent` (what `execution/gates.py`
prefers) is unaffected and the code labels the output market-adjusted, so this
is a fit/serve PRICE mismatch, not a mislabelled probability. Deliberately not
fixed: it is a live-serving behaviour change (the same class step 08 deferred),
outside this work order's experiment scope. See D44.
