## Pipeline (`reports/improvement/13/`)

1. `01_freeze_manifest.py` — the manifest above.
2. `02_train_xgboost.py` — trains XGBoost indep (`PRICE_FREE_FEATURE_COLS`) +
   market (`FEATURE_COLS`) on dev_core (mirrors step 10's `run_catboost`),
   scores the 618-race eval panel, merges `xgboost_{indep,market}_prob` into a
   copy of `data/audit/12/eval_panel_scored.parquet` ->
   `data/audit/13/eval_panel_scored_with_xgb.parquet`. 328s wall.
3. `03_oof_blend_dev.py` — chronological walk-forward OOF (`group_time_series_
   split`, dev_core, n_splits=6) for CatBoost/LightGBM/XGBoost, indep+market,
   **fixed hyperparameters per fold, no re-tuning** (CatBoost/XGBoost reuse
   their own dev_core-tuned `best_params`; LightGBM uses its existing untuned
   defaults — the same disclosed asymmetry as step 10's manifest) and a fixed
   500-round cap (no early stopping) — a full nested re-tune across 3 GBDT
   families x 6 folds x 2 branches is outside this stage's CPU budget, the
   same economisation step 12 disclosed for its own conditional-logit-only
   walk-forward panel. 227,265/263,982 dev_core rows got OOF coverage
   (36 fold-fits; 2,356s wall, LightGBM's fixed-round fold fits dominate —
   CatBoost(GPU)/XGBoost(CPU hist) fold fits are fast by comparison).
4. `04_evaluate.py` — selects blend weights on blend_dev OOF rows (35,298
   rows/4,138 races) by exhaustive grid search over `{0,0.25,0.5,0.75,1.0,
   1.5,2.0}` per model (0 allowed, never forced nonzero — scope item 4), fits
   a calibrator per blend on calib-window OOF rows (16,606/1,874 races,
   genuinely out-of-fold), applies the FROZEN weights+calibrator to the eval
   panel, scores every individual learner and both ensembles via `models.
   head_to_head.head_to_head`, and race-clustered bootstraps (2,000
   resamples) each candidate's gap vs market and the 3-model-minus-2-model
   delta. 278s wall. **Bug found and fixed mid-stage**: the first run's
   bootstrap scored raw, non within-race-normalised probability columns,
   disagreeing with `head_to_head`'s own normalised numbers printed one line
   above; fixed (`_normalized`/`_PRE_NORMALISED_PREFIXES`) and re-run —
   corrected bootstrap means now match the point-estimate gaps.

(328s total, dev_core = 263,982 rows). OOF walk-forward (03): 2,356s (6 folds

OOM observed on the 32GB-RAM machine across the full pipeline.

## Unresolved limits

- OOF walk-forward uses FIXED hyperparameters (no per-fold re-tuning) and a
  capped 500-round budget — a full nested tune was outside this stage's CPU
  budget (disclosed in the manifest, same economisation class as step 12). A
  fold-level re-tune could in principle shift the picked weight, though the
  eval-panel individual scores (each model's own dev_core-tuned params) also
  show XGBoost is not the strongest branch either way.
- Blend-weight grid is a fixed 7-point-per-model simplex (0/0.25/.../2.0),
  not a continuous optimiser — matches step 12's `ALPHA_GRID`/`BETA_GRID`
  precedent for a "simple blend"; a stacking meta-learner was not built since
  this result (zero XGBoost weight, zero measured delta) already answers the
  question without further complexity (AGENTS.md scope guidance).
- All step 07-12 deferred items stand unchanged (STATE.md blockers) — D44's
