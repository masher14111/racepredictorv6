## Defect 1 (fixed): historical-result settlement join was horse-ID-first, global

`scripts/daily_paper_loop.py::_index_results` indexed the `betsp` results
store on `horse_id` alone, with no venue or date restriction — `by_id[str(
horse_id)] = row`, last write wins across the **entire** results list, any
date, any course. `_settle_open_tickets` tried this global index before any
venue/date check. Verified on the real store: **35,913 of 40,633** distinct
`horse_id` values (88%) recur across more than one `race_date` — a horse
running more than once a season is the normal case, not an edge case — so
any settlement run had a high chance of joining a ticket to a different
race's result. Reproduced directly (`reports/improvement/08/...md` §1):
the pre-fix algorithm settles a losing ticket "won" from an unrelated
Doncaster race, purely because that row happened to be read last.

Fix: `_identity_key()` builds a canonical `(venue, off-time-to-the-minute,
horse)` tuple per row (deliberately **not** reusing
`execution.snapshots.race_uid`, which drops venue — see Defect 3 below).
`_index_results` now returns a canonical index plus two day/venue-scoped
fallbacks (`by_fallback_id`, `by_fallback_name`) for rows whose `race_date`
carries no time-of-day. A key that collects two rows disagreeing on the
finishing position is dropped from its index rather than "last write wins";
`_settle_open_tickets` refuses to settle (leaves the ticket open) rather
than pick one. `TicketStore.settle`'s own "already settled" guard (Deferred
in step 07, verified again here) keeps a re-run financially idempotent.

## Defect 2 (fixed): forward report conflated PASS decisions with open wagers

`_paper_summary` (in both `scripts/daily_paper_loop.py` and
`scripts/paper_betting.py`, duplicated) built `n_open`/`n_settled` from
**every** ticket row regardless of `decision`. On a NO-GO day every decision
is PASS (no stake, never a bet), so the "988 open tickets" figure recorded
in STATE.md/DECISIONS.md was always 988 disclosure records, not open
wagers. Verified against the real production ledger: `TicketStore.to_frame()`
-> 988 rows, `{'PASS': 988}`, 0 settled, 0 CANDIDATE. Fix: `_paper_summary`
now reports `n_pass`/`n_candidates` alongside `n_tickets`, and scopes
`n_open`/`n_settled` to CANDIDATE decisions only. `execution/report.py`'s
forward-validation report and `ui/forward_validation.py` render both counts
explicitly ("Decisions logged: N (P PASS, Q candidate)" / "Candidate tickets
(paper wagers): Q (open, settled)"). Re-verified against real production
data after the fix: `n_tickets=988, n_pass=988, n_candidates=0, n_open=0`.

## Defect 3 (found, deliberately NOT fixed this stage): `race_uid` drops venue

`execution/snapshots.py::race_uid()` returns the off-time string alone
(`_RACE_TIME_FMT`, no venue) whenever the off-time parses — venue is only a
last-resort fallback when no time is available. Two meetings sharing an
exact post time therefore collapse to one `race_uid`. Reproduced on the real
store: **4 of 35,107** unique off-times in `data/historical/betsp.parquet`
have more than one venue (e.g. Leopardstown and York both off at 16:15 on
2024-05-17) — real, ~0.011% of off-times. This function is shared by
`execution.gates.race_uid`, `execution.tickets.Ticket.race_uid`, and
`execution.snapshots.SnapshotStore`'s own keying (odds snapshots, closing
quotes). Step 08's own settlement fix (Defect 1) does not reuse this
function — it builds its own venue-explicit key — so win/lose/void
determination is not exposed to this collision. `SnapshotStore.closing_quote`
(CLV only, not P&L) still keys on it and remains exposed at this rate.
**Not fixed here**: correcting it means changing the on-disk identity format
across `odds_snapshots` and `paper_tickets` (schema/data migration,
re-verification of steps 03/06/07's dependent tests) — out of proportion to
a ~0.011% CLV-only exposure and beyond this stage's settlement-identity
remit. Named, not silently carried forward.

## Defect 4 (found, deliberately NOT fixed this stage): Rule 4/dead-heat/each-way/non-runner never reach live settlement

`execution/settlement.py::settle_ticket` (Rule 4, dead heat, each-way,
non-runner void, commission) is called **only** by `execution/simulator.py`
(the offline backtest). The live loop's `_settle_open_tickets` ->
`TicketStore.settle()` computes win/lose directly via
`backtest.metrics.settle(stake, odds, 1.0/0.0, commission)` — no Rule 4, no
dead-heat divisor, no non-runner void, no each-way place leg, ever, for a
real paper ticket. `execution.race_facts` (the Sporting Life archive parser
that builds the richer `RaceResult` this needs) is verified to have real,
current coverage — `data/historical/raw/sporting_life/2026/2026-09-17`
parses to real finish positions and `ride_status` 2 days before this
session's "today". This is an actionable gap, not a missing-data blocker.
**Not fixed here**: wiring it in is a live-settlement-path architecture
change (horse-key normalisation differs between `race_facts` (`norm_horse`)
and tickets (`execution.snapshots.horse_key`), cache-freshness handling,
each-way terms round-trip, new test coverage) beyond this stage's identity/
reporting acceptance criteria and this session's remaining budget.
`execution/settlement.py`'s own test suite (`tests/execution/test_settlement.py`,
`tests/execution/test_race_facts.py`, 83 tests) was re-run in isolation this
stage and confirmed unaffected — nothing here broke it, it was simply never
called from the live loop, before or after this stage.
