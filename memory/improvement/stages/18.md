## Bounded integration fix (does not change the evaluated model)

**D50: live refresh crashed on an all-null `runner_status` column read through pandas' pyarrow
backend.** `scripts.refresh`'s first run today failed in `models/predictor.py::_is_non_runner`:
`status.fillna("").astype(str)` raised `pyarrow.lib.ArrowInvalid: Invalid null value`. Root cause:
an all-null column converted through the pyarrow dtype backend is inferred as `null[pyarrow]`, and
boxing the fill value `""` into that type fails (reproduced standalone in 3 lines). This is exactly
B8's condition (`runner_status` null on every row because no declared card has arrived) meeting a
dtype path that step 17's fixed-data replay never exercised, because replay used static parquet
inputs, not this cycle's live-scraped frame. Fix: `.astype(object)` before `.fillna("")` on both the
`runner_status` and `jockey_name` reads in `_is_non_runner` (`models/predictor.py:224-231`). This
only changes how a null status/jockey string is normalized before a string comparison; it does not
touch any trained model, feature, or served bundle. Regression test added:
`tests/models/test_predictor.py::test_all_null_runner_status_as_pyarrow_null_dtype_does_not_crash`
(constructs the real `null[pyarrow]` dtype via `convert_dtypes(dtype_backend="pyarrow")`, not a
Python `None` scalar — the existing `test_null_runner_status_keeps_the_whole_field` predates this
dtype and did not catch it).
